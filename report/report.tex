\section{Summary}
I tested the OsdagBridge Plate Girder module in two complementary ways:
\begin{enumerate}
\item \textbf{Manual GUI testing on Windows 11}, with a small launcher (\code{run_logged.py}). It records, for every \emph{Design} click, the input dictionary the UI sends, the backend's normalised input, the full output dictionary, the console log and a diff against the previous run. OsdagBridge's source is not modified.
\item \textbf{An automated test suite} (\code{run_test_suite.py}). It drives the \emph{real} homepage \code{InputDock}, the real \emph{Additional Inputs} dialog, the real custom-material dialog, \code{.osi} save/load and the backend off-screen. The dictionary it builds matches, key for key, the dictionary the real GUI produced in my manual runs (576 keys, test U1). So each automated run reproduces what a user does.
\end{enumerate}

\noindent The suite performed \textbf{\input{generated/n_designs.tex}design runs} and \textbf{\input{generated/n_checks.tex}automatic checks} (Section~\ref{sec:results}). The main results:
\begin{itemize}
\item \textbf{Works well:} homepage hard validation (span, carriageway, skew: every valid and invalid boundary behaved as specified); 3 consecutive identical runs give identical outputs; returning to an earlier input set gives the earlier result; a failed run leaves no stale backend data; custom $f_y$, $E$, $f_{ck}$, $f_{ctm}$, $E_{cm}$ reach the design.
\item \textbf{8 new defects reported} (Table~\ref{tab:issues}). The most significant: the LTB unbraced length depends on whether the Additional Inputs dialog was ever saved (\issue{01}); the number of girders depends on typing history (\issue{02}); the deck-edge lines are designed as girders, which makes girder self-weight demand $\approx n/(n+2)$ of $wL^2/8$ (\issue{03}); and deflection is reported with two different values and two different verdicts (\issue{04}).
\item \textbf{4 comments} adding new evidence to existing issues (\gh{71}, \gh{19}, \gh{43}, \gh{96}). Defects that other applicants had already reported were \emph{not} re-filed; they are cross-referenced in the result tables.
\item \textbf{2 fix pull requests} with regression tests: \pr{219} (\issue{08}) and \pr{220} (\issue{02}), Section~\ref{sec:fixes}.
\end{itemize}

\section{Method}
\subsection{Manual GUI runs with \texttt{run\_logged.py}}
\code{run_logged.py} wraps \code{PlateGirderBridge.set_input()} and \code{design()} at runtime and then starts the app's own \code{main()}. Each Design click writes:
\begin{itemize}
\item \code{runNN_ui_input.json}: the input dictionary the UI sent;
\item \code{runNN_backend_input.json}: the backend's normalised input;
\item \code{runNN_output.json}: the full output dictionary (the UI itself cannot export it: its \emph{Save Outputs (.csv)} menu item has no handler, see \gh{53});
\item \code{runNN_meta.json} and \code{runNN_diff_vs_prev.txt}: run status, timing, and a key-by-key diff against the previous run.
\end{itemize}
The whole console goes to \code{session.log}.

\subsection{Automated suite}
\code{run_test_suite.py} creates the real \code{InputDock} and \code{AdditionalInputs} widgets off-screen and replays the small glue methods of \code{TemplatePage} (Design pre-steps, \code{update_cad_from_inputs}, Save/Load Input, unlock), citing the source lines they mirror. Typing into a field calls the same \code{_on_field_edited} handler the \code{editingFinished} signal calls. Pop-ups and the custom-material dialog are answered programmatically, and the real \code{_validate_and_save()} runs. One backend is reused across the runs of a session with \code{backend.reset()} in between, exactly as the GUI's unlock does.

\paragraph{Self-test.} Building TC00 (and TC01, custom materials) through the simulated GUI gives a dictionary identical to the one recorded from the real GUI on Windows (U1a, U1b: 0 differences in 576 keys).

\paragraph{Platforms.} The suite ran on my Windows 11 laptop (31 designs, 23 minutes; the run used in this report) and, as a cross-check, headlessly on Linux. For the 31 runs the two platforms have in common, every number compared (girder count, $M_{SW}$ ratio, deflections, areas, $f_y$, spacing, exposure, max DCR) is identical.

\paragraph{Automatic checks per design run.} Table~\ref{tab:checks} lists the twelve checks applied to every design. Expected values come from the inputs (e.g.\ density entered, number of girders), from hand calculation ($wL^2/8$) or from consistency (the same quantity reported in two places).

\noindent Further findings: after \emph{Save $\to$ Load}, the custom deck properties become \code{None} and Design stops with \code{'material.deck.fck' is required} (S04, already in \gh{19}). \subsection{Additional Inputs propagation}
\begin{itemize}
\item Deck thickness 300~mm, wearing course 80~mm, $\gamma_{m0}$ 1.15, wind height 15~m, left support Fixed and stud diameter 22~mm all reach the design after \emph{Additional Inputs $\to$ Save} (A1: slab load 7500~N/m$^2$). \pass
\item They are all reset to defaults when a homepage field changes (U3a, A2), by Save Input (U3b, file \emph{and} live session), and by Load Input even when the file contains them (U3c). \fail\ Comment on \gh{71}.
\item Opening Additional Inputs and pressing Save \emph{without edits} changes the design: cross-bracing spacing $3\to15$~m, $\chi_{LT}$ $1.0\to0.328$, $M_b$ $7986\to2621$~kNm (S11, A3). The girder area is also rounded to 3 significant figures (A4). \fail\ \issue{01}.
\item Five girders requested in Typical Section: the design check covers 7 lines (C01). \fail\ \issue{03}.
\end{itemize}

\section{Limitations}
\begin{itemize}
\item The suite builds widgets but not the main window. CAD drawing, plots and the output dock were checked manually (Section~\ref{sec:cad}), not automatically.
\item Engineering expectations were limited to what can be derived from the inputs and the codes cited in the software (IRC~6/22/112, IS~2062). The issues report inconsistencies; they do not certify a correct design.
\item Every number in this report can be regenerated with the scripts in the evidence repository (Appendix~\ref{app:repro}).
\end{itemize}
